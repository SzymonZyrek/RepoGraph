# Consumer boundaries

Hacka uses an exact target revision and bounded CLI answers to collect implementation, validation, contract and documentation evidence. Context budgets and task choices belong to Hacka.

VibeGuard uses the library with explicit confirmed/advisory capability overlays. Review/Owner authority remains entirely in VibeGuard. Direct/transitive/shared impact and sibling exclusion must be demonstrated through its actual adapter against a pinned packed artifact.

Stynk can filter returned Artifact roles for validation, inspect explanations, and fall back conservatively when evidence is partial/truncated/unavailable. RepoGraph does not construct test commands or decide which tests may be skipped. #83 is an additional consumer proof, not a reason to add Stynk-specific APIs.

The RepoGraph fixture in test/bounded-consumers.test.ts is a generic contract regression. It is not proof of a deployed application integration. Real adapter/package evidence is recorded after consumer validation; public-release completion is unproven until those checks pass.
