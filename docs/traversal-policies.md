# Traversal policies (0.0.3)\n\nRepoGraph keeps graph facts separate from the question being asked. A traversal policy selects which facts are allowed to participate in a bounded query.\n\nA policy can constrain direction, edge kinds, destination node kinds, evidence method, fact origin, authority, evidence state, stop-node kinds, maximum depth and maximum returned nodes.\n\nPolicies use schema `repograph.traversal-policy/v1` and serialize canonically, so non-TypeScript callers can persist or send the same policy through the CLI boundary.\n\n## Semantics\n\nAn edge is traversable when its kind is allowed and at least one provenance record satisfies all configured evidence constraints. Explanations preserve the full graph edge and separately report the provenance records that matched the policy.\n\nThis keeps deterministic imports, external-index evidence and authoritative consumer overlays distinct. RepoGraph does not collapse them into a numeric confidence score.\n\n## Results\n\n`traverseWithPolicy()` returns a deterministic slice plus one first-discovery reason per selected node: previous node, edge, depth and matching provenance.\n\n`explainWithPolicy()` returns a deterministic shortest causal path with matching provenance attached per hop.\n\n`truncated` means a configured work/depth bound prevented complete traversal. `partial` is true when traversal was truncated or when the underlying graph contains partial/unresolved diagnostics or provenance.\n
