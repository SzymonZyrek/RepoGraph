# Bounded index/query evaluation

The 0.0.6 query workload is a small causal answer from a pinned repository/ref. Full GraphDocument serialization is not a performance target.

Local Windows x64 / Node 24.19.0 observations, 2026-10-05, from `scripts/eval-index.mjs`: independent Python artifact clusters with explicit Markdown implementation/validation links. The fixture uses deterministic non-code providers, not a source-code parser. Results include opening and closing the disk-backed index. The full test suite ran concurrently, so timings are indicative, not isolated latency guarantees. Raw output is `.cache/index-query-economics.json`, not committed product data.

Every ordinary edit refreshed one provider-owned artifact fact, with no documentation blob reparsing. Rename-only Markdown reused unchanged blob syntax (zero reparses). Deleting the database/cache and rebuilding produced equivalent bounded answers. Query result size stayed constant as the repository grew 16 times; repository-sized index maintenance is separate from bounded response materialization.

Cold indexing is still expensive: the importer performs per-artifact native writes and separate Git reads for documentation. Native batch import/blob batching should be evaluated using this workload before making latency promises. Path-set changes re-resolve documentation providers to account for newly resolved/missing references; this is conservative and does not reparse unchanged blob syntax. The index has no runtime daemon and pays native open/process startup cost. These are measured limitations, not claims of changed-files-only total cost.

## Schema admission and query value

| Persisted fact | Question improved | Worse without it | Update cost |
|---|---|---|---|
| Artifact identity/path | Which concrete files need attention? | No actionable file result | Changed Git path/blob claim |
| Six optional artifact roles | Which validation/docs/contracts/build/config/generated files are relevant? | Cannot select result classes without rereading files | Provider/convention claim refresh |
| Boundary kind/key | Which explicit capability/workspace/interface is reached? | File-only paths miss logical/contract surfaces | Owning provider refresh |
| `DEPENDS_ON` | What may need re-evaluation, and why? | No causal reverse impact | Source provider replacement |
| `CONTAINS` | Which boundary contains the affected artifact? | Cannot reach a capability without fabricating runtime dependency | Overlay/native membership replacement |
| Compact evidence reference | Which provider/authority supports the selected path? | Derived facts can be mistaken for policy | Provider-owned evidence refresh |
| Revision/config metadata once | Is the answer about the requested revision? | Stale evidence can appear current | Atomic metadata update |

The current model has two node categories, two relation kinds and six optional functional roles. Private provider fingerprints and ownership claims earn their storage cost by reusing inputs and refreshing converging facts atomically; they are not returned as intelligence.
