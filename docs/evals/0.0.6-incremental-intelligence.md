# 0.0.6 incremental composed-intelligence evaluation

Measured on 2026-10-04 after the final local CI run. This is a local Windows result, not the earlier Linux Actions timing from #62. No latency pass threshold was chosen.

Environment: win32/x64, v24.19.0, git version 2.50.1.windows.1; AMD Ryzen 5 7535HS. Measured implementation: `6213cff`, including current main `6f05ca7` (#64), first-parent fragment reuse and regional package/configuration maintenance.

The [raw evidence](0.0.6-incremental-intelligence.json) records full commit and parent SHAs, changed paths and before/after blob identities, counts, structural edge deltas, reverse affected slice sizes, phase timings, wall times and warm/cold equality assertions.

## Method

The opt-in harness grows independent clusters from 24 to 96 to 384, holding each cluster at ten source files and editing the same bounded cluster surface. At each size it builds the initial revision, eight sequential one-file commits, an unchanged-blob leaf rename, a one-file dependency edit, a broad whole-source comment edit, and a stale exact-SHA query after HEAD advances. Every initial/revision/stale warm graph is asserted equal to its cache-disabled cold graph, including metadata, diagnostics and exact provenance.

Warm builds use the persistent store, including disk reads; the harness does not substitute an in-memory graph memo. Cold builds disable the store and use the same batched Git reader and fragment materializer. Syntax-cache I/O is charged to cache time, not extraction/resolution. Full graph materialization and the canonical JSON serializer used by the CLI are measured separately. Serialization is outside library warm/cold wall time.

History creation, batched Git-diff auditing, graph equality assertions and reverse-slice queries occur outside measured build wall time. Narrow diff records are asserted equal to the public Git-diff API. Narrow reverse slices use public affectedClosure; the broad acyclic fixture uses an indexed union and asserts the expected affected count. Completed size evaluations are checkpointed atomically, and resume requires matching compiled-code/harness fingerprints. No partial checkpoint is published as final evidence.

## Architecture and remaining scaling limits

- Exact-commit manifests and compatible first-parent manifests reuse normalized Git, source and relationship fragments. No historical-cache baseline search is performed.
- Candidate indexes include failed import resolutions and extension-priority alternatives. Additions, deletions, renames and parser-mode changes have behavioral coverage; content-only source edits retain package/test facts.
- Immutable packs hold at most 64 fragments. Unrelated facts are not rehashed or encoded on ordinary edits. Snapshot manifests reference all packs directly, and missing index/pack artifacts rebuild the same immutable snapshot rather than returning partial evidence.
- Full snapshot-index/manifest encoding, reading all referenced packs, constructing file indexes/aggregate counts, provenance materialization, canonical ordering and JSON output still scale with repository/graph size. The full-graph API requires full output; the remaining snapshot-index and pack-read costs are explicit, not claimed to be proportional to changed files.
- Package manifest edits reparse changed manifests and invalidate indexed declaration/dependency/membership regions, including unresolved workspace candidates. TS configuration edits re-resolve configuration-dependent importers while preserving package/test facts. CODEOWNERS and incompatible ingestion/analysis settings use conservative cold invalidation.
- Intelligence index/pack fingerprints verify cached payload bytes, including corruption that remains valid JSON. Cached normalized fact IDs are not rehashed. Explicit path-rule overlay identity/advisory authority is valid under the existing graph contract, and original optional commit absence is preserved.
- Results come from one local machine and one run per size. They do not establish portable timing thresholds or directly compare to the differently hosted #62 Actions run.

The bounded maintenance and pack-encoding counters are proven. **Issue #61 remains open**: the stronger whole-call changed-surface criterion is not established, because full snapshot reads/index persistence and full materialization/output remain size-dependent. This PR delivers the architectural maintenance improvement and transparent economics, without claiming the entire consumer call is O(changed files). Further work should target the measured dominant cache/index phase while preserving the selected full-graph API.

## Reproduce and validation

```sh
npm install
npm run ci
npm run build
node scripts/eval-intelligence.mjs > intelligence-economics.json
```

`npm run eval:intelligence` is the equivalent opt-in build-and-evaluate command. Economics is excluded from required CI.

Final local `npm run ci`: 101 tests passed; line coverage 92.57%, branch coverage 81.61%, function coverage 98.34%. Existing thresholds remain 80% lines, 70% branches and 80% functions. The Git symlink fixture constructs a mode-120000 Git object, exercising pinned Git semantics on Windows without native symlink privileges. Focused coverage also verifies regional package/config invalidation, valid-JSON payload corruption, old standalone-graph compatibility and aggregate source content above 64 MiB with bounded per-blob reads.
